# AI DevCoach — 개인별 학습진도관리 상세 화면설계서

화면설계서 v1.0 | 기능 ID: FR-04 | 연계: FR-02 수준 진단, FR-03 학습계획, FR-05 GitHub 분석, FR-08 성과 분석

## 1. 화면 설계 개요

### 1.1 개발 목적

학습자가 AI DevCoach에서 수립한 개인별 학습계획을 기준으로 주차별·과제별 학습 진행 상황을 확인하고, 학습 결과물을 제출하며, 계획 대비 실적을 관리할 수 있는 화면을 구현합니다.

AI Agent는 학습 이력과 미완료 과제를 분석하여 다음 학습 행동을 제안합니다. 단, 과제 완료 여부와 실제 학습시간은 검증 가능한 기록을 기준으로 관리합니다.

|---|---|---|

## 4. UI-15 학습진도 대시보드 상세 명세

### 4.1 KPI 표시 항목

|항목 ID|항목명|계산·표시 방식|
|---|---|---|
|DB-01|전체 과제 완료율|완료 과제 수 ÷ 전체 과제 수 × 100|
|DB-02|누적 학습시간|학습시간 기록 합계|
|DB-03|계획 학습시간|승인된 과제별 예상시간 합계|
|DB-04|진행 중 과제|`in_progress` 상태 과제 수|
|DB-05|보류 과제|`blocked` 상태 과제 수|
|DB-06|주차별 완료율|해당 주 완료 과제 수 ÷ 해당 주 전체 과제 수 × 100|
|DB-07|AI 코칭 요약|최근 진도·지연 과제에 근거한 추천|

주의: 완료율과 학습시간 달성률은 다른 지표입니다. 학습시간이 많더라도 과제 완료 기준을 충족하지 않았다면 완료율이 올라가지 않습니다.

### 4.2 상태별 UI 표시 규칙

|상태|의미|화면 표시|
|---|---|---|
|`todo`|학습 시작 전|시작 전|
|`in_progress`|학습 수행 중|진행 중|
|`completed`|완료 기준 충족|완료|
|`blocked`|학습 진행 장애|보류|

학습자가 완료를 요청했더라도 GitHub 결과물 검증이 필요한 과제라면 `completion_requested` 상태를 추가하여 검증 전과 완료 확정을 구분할 수 있습니다.

## 7. UI-18 학습 이력 및 통계

### 7.1 통계 지표

|지표|계산 방법|활용 목적|
|---|---|---|
|과제 완료율|완료 과제 / 전체 과제|학습 진행 수준|
|학습시간 달성률|실제 학습시간 / 계획 학습시간 × 100|계획 대비 투입시간|
|주차별 진도율|주차별 완료 과제 / 주차별 전체 과제|주간 진행 현황|
|과제 지연 수|마감일 경과 및 미완료 과제 수|일정 위험 파악|
|평균 과제 수행시간|완료 과제의 실제시간 평균|계획시간 적정성 검토|
|결과물 제출률|결과물 제출 과제 / 제출 대상 과제|실습 수행 여부|
|학습 연속일|실제 학습 기록이 있는 연속 날짜 수|학습 지속성 확인|

시간 달성률이 100%를 초과할 수 있으므로, 대시보드 그래프는 100%까지만 표시하더라도 실제 수치는 별도로 유지합니다.

### 7.2 활동 이력

활동 이력은 다음 정보를 기록합니다.

- 학습 시작·중단·완료
    
- 실제 학습시간 등록 및 수정
    
- GitHub 결과물 제출
    
- 완료 요청 및 검증 결과
    
- AI 코칭 생성
    
- 학습계획 변경 요청
    

각 이력에는 `user_id`, `task_id`, `event_type`, `event_time`, `old_value`, `new_value`를 저장합니다.

## 9. 데이터베이스 설계

기존 `learning_plans`, `learning_plan_weeks`, `learning_tasks`를 활용하고, 진도관리용 테이블을 추가합니다.

|테이블|주요 필드|용도|
|---|---|---|
|`learning_tasks`|task_id, week_id, status, due_date, completed_at|과제 상태|
|`learning_time_logs`|log_id, task_id, user_id, learning_date, duration_minutes|실제 학습시간|
|`task_submissions`|submission_id, task_id, github_url, commit_sha, submitted_at, status|결과물 제출|
|`task_verifications`|verification_id, submission_id, result, evidence, checked_at|완료 검증|
|`learning_activity_logs`|activity_id, task_id, event_type, old_value, new_value, created_at|활동 이력|
|`coaching_feedback`|feedback_id, user_id, plan_id, analysis, recommendation, created_at|AI 코칭 기록|

학습시간은 합계 필드 하나만 덮어쓰는 방식보다 날짜별 시간 기록을 누적하는 방식이 적합합니다. 이렇게 하면 주간·월간 통계와 학습 이력의 정확성을 높일 수 있습니다.

## 13. 최종 완료 기준

FR-04 개인별 학습진도관리 기능은 다음 사항을 모두 충족해야 합니다.

- 승인된 개인별 학습계획과 과제를 조회할 수 있다.
    
- 전체·주차별 과제 완료율을 정확하게 계산한다.
    
- 학습자가 과제 상태와 실제 학습시간을 기록할 수 있다.
    
- GitHub 결과물 또는 학습 증빙을 제출할 수 있다.
    
- 완료 기준에 따라 과제 완료를 확인한다.
    
- 학습시간·과제 변경 이력을 보관한다.
    
- AI가 학습 진행 상황을 분석하고 다음 행동을 추천한다.
