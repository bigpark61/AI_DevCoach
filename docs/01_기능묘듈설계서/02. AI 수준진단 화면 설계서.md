## 1. 화면 설계 개요

목적: AI DevCoach에 등록한 학습자의 실제 개발 역량을 진단하고, 영역별 강점·약점을 분석하여 개인별 학습계획을 수립하기 위한 기초 데이터를 생성합니다.

진단은 객관식 20문항 + 코드 이해·오류 분석형 2문항, 총 22문항으로 구성합니다. 정답이 명확한 문제는 규칙 기반으로 채점하고, 서술형 코드는 평가 기준표에 따라 AI가 분석하되 검증 가능한 채점 근거를 저장합니다.

### 서술형 AI 채점 루브릭

|평가 기준|배점(문항당)|평가 내용|
|---|---|---|
|문제 원인 이해|4점|오류나 코드 동작 원인을 정확하게 파악|
|해결 방법|4점|실행 가능한 수정 방법 제안|
|설명의 명확성|2점|논리적이고 이해하기 쉬운 설명|

LLM은 채점 근거와 점수를 구조화된 형식으로 반환해야 합니다. 다만 서술형 채점은 모델에 따라 달라질 수 있으므로, 대표 답안에 대한 기준 점수와 비교하는 검증 절차가 필요합니다.

### 수준 분류 기준(초안)

|총점|수준|권장 학습 방향|
|---|---|---|
|0~39점|입문|Python, Git, API 기초|

이는 프로젝트 운영을 위한 제안 기준이며, 실제 문항 난이도와 파일럿 진단 결과를 확인한 뒤 조정해야 합니다. 총점뿐 아니라 영역별 점수로 학습계획을 결정합니다.

### 6.1 AI 평가 Agent 역할

AI 평가 Agent는 모든 진단을 처리하는 것이 아니라, 서술형 답안 분석과 학습 피드백에 집중합니다.

- `get_assessment_questions()` — 문항 및 평가 기준 조회
    
- `save_assessment_answer()` — 사용자 답안 저장
    
- `grade_objective_answers()` — 객관식 정답 비교
    
- `evaluate_code_answer()` — 서술형 답안 루브릭 평가
    
- `calculate_skill_scores()` — 영역별 점수 산출
    
- `save_skill_profile()` — 진단 결과 저장
    
- `generate_learning_feedback()` — 강점·취약점 및 추천 학습 생성
    

정답 및 채점 루브릭은 서버에서만 관리하고, 답안 평가 시 사용자가 입력한 텍스트를 시스템 명령으로 취급하지 않도록 분리합니다.

## 7. 데이터베이스 설계

|테이블|주요 컬럼|용도|
|---|---|---|
|`assessment_questions`|question_id, category, type, content, options, version|문제은행|
|`assessment_rubrics`|rubric_id, question_id, criteria, max_score|채점 기준|
|`assessment_sessions`|session_id, user_id, status, started_at, submitted_at|진단 세션|
|`assessment_answers`|session_id, question_id, answer, score, feedback|답안 및 채점|
|`assessment_results`|result_id, session_id, total_score, level, skill_scores|종합 결과|
|`learner_skill_profiles`|user_id, category, score, assessed_at|최신 역량 프로필|

### API 명세

|Method|Endpoint|기능|
|---|---|---|
|POST|`/api/assessments/start`|진단 세션 생성|
|GET|`/api/assessments/{session_id}/questions`|진단 문항 조회|
|PATCH|`/api/assessments/{session_id}/answers`|답안 임시 저장|
|POST|`/api/assessments/{session_id}/submit`|답안 최종 제출|
|GET|`/api/assessments/{session_id}/result`|채점 결과 조회|
|GET|`/api/assessments/history`|진단 이력 조회|

`submit` API는 중복 요청이 발생해도 동일 세션이 중복 채점되지 않도록 설계합니다. 서술형 채점이 오래 걸리면 `grading` 상태를 반환하고 결과 조회 API에서 완료 여부를 확인합니다.

## 9. 개발 우선순위 및 구현 일정

|단계|구현 내용|예상 시간|
|---|---|---|
|1|문제은행 22문항 및 정답·루브릭 설계|5h|
|2|진단 시작·문제 풀이 화면 개발|5h|
|3|답안 저장·객관식 채점 API|4h|

24시간은 기존 240시간 프로젝트 계획의 세부 작업에 포함되는 목표 공수이며, 별도 추가 시간이 아닙니다. 서술형 AI 평가의 품질 검증에는 별도 통합 테스트 시간을 활용합니다.

## 10. 최종 완료 기준

수준 진단 기능의 개발 완료는 다음 조건을 모두 충족하는 것으로 정의합니다.

1. 사용자가 총 22문항에 응답하고 제출할 수 있다.
    
2. 객관식 20문항이 정해진 정답 기준으로 자동 채점된다.
    
3. 서술형 2문항이 명시된 루브릭에 따라 평가되고 근거가 기록된다.
    
4. 종합 점수와 5개 영역별 점수가 일관되게 계산된다.
    
5. AI가 진단 결과를 바탕으로 강점·약점과 학습 방향을 설명한다.
    
6. 진단 결과가 사용자 프로필에 연결되고, FR-03 개인별 학습계획 생성에 실제 입력 데이터로 활용된다.
    

설계의 핵심은 AI가 학습자의 실력을 막연히 추정하는 것이 아니라, 검증 가능한 진단 결과를 바탕으로 학습을 추천하는 구조입니다. 이를 통해 이후 GitHub 코드 리뷰 결과와 진단 점수를 비교하여 학습자의 역량 변화를 추적할 수 있습니다.
