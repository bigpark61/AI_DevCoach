화면설계서 v1.0 | 기능 ID: FR-05 | 연계: FR-03 학습계획, FR-04 학습진도, FR-06 AI 코드 리뷰, FR-08 학습성과 분석

## 1. 기능 개요

### 1.1 개발 목적

학습자가 GitHub에 등록한 프로젝트 저장소를 AI DevCoach에 연결하면, 시스템이 프로젝트 구조, 기술 스택, 코드 구현 현황, README, Commit 이력, 학습과제 수행 여부를 분석하고 학습자의 개발 역량과 개선사항을 제공하는 기능입니다.

단순한 GitHub 저장소 조회가 아니라 다음 세 가지를 핵심으로 설계합니다.

1. 프로젝트 분석: 저장소 구조, 주요 기능, 기술 스택, 문서화 수준 파악
    
2. 학습 성과 검증: 개인별 학습계획의 과제 요구사항과 실제 GitHub 결과물 비교
    
3. AI 개선 제안: 코드 품질, 미구현 기능, 보완할 기술과 다음 학습 방향 추천

### 5.2 파일 상세 화면

파일을 선택하면 다음 정보를 표시합니다.

- 파일 경로 및 파일 크기
    
- 마지막 변경 Commit
    
- 파일 역할에 대한 AI 설명
    
- 주요 클래스·함수
    
- 발견된 문제점
    
- FR-06 AI 코드 리뷰 실행 기능
    

MVP에서는 전체 파일을 무조건 LLM에 전달하지 않고, 파일 목록 → 중요 파일 선택 → 필요한 내용만 분석하는 구조를 권장합니다.

### 8.3 AI 평가 근거

AI가 문제점을 제시할 때는 가능하면 다음 근거를 함께 저장합니다.

```
{
  "finding_id": "F-001",
  "category": "error_handling",
  "severity": "medium",
  "description": "API 예외 처리 확인 필요",
  "evidence": [
    {
      "file": "backend/main.py",
      "line_start": 25,
      "line_end": 32
    }
  ],
  "recommendation": "외부 API 오류 및 타임아웃 처리 추가",
  "verification_status": "needs_review"
}
```

라인 번호는 분석 대상 Commit SHA와 함께 기록해야 하며, 실제로 수집한 파일에 존재하는 범위만 인용해야 합니다.

### 9.2 과제 평가 예시

|학습과제|완료 기준|GitHub 확인 증거|평가|
|---|---|---|---|

### 9.3 학습 진도 반영 정책

GitHub 분석 결과는 `task_verifications`에 저장하고, 과제 상태를 자동으로 변경하기 전 완료 기준을 확인합니다.

권장 상태는 `미검증 → 분석 중 → 충족 / 보완 필요 / 확인 불가`입니다. 학습자가 재제출하면 새로운 분석 이력을 생성하고 이전 결과를 보존합니다.

### 10.2 GitHub API 사용

공식 문서: [GitHub REST API](https://docs.github.com/en/rest?utm_source=chatgpt.com)

|API|사용 목적|
|---|---|
|`GET /repos/{owner}/{repo}`|저장소 정보|
|`GET /repos/{owner}/{repo}/git/trees/{tree_sha}`|파일 구조|
|`GET /repos/{owner}/{repo}/readme`|README|
|`GET /repos/{owner}/{repo}/commits`|Commit 이력|
|`GET /repos/{owner}/{repo}/contents/{path}`|파일 내용|

실제 구현에서는 파일 수와 크기 제한, 페이지네이션, API 호출 제한, 비공개 저장소 접근 권한을 고려해야 합니다.

비공개 저장소 접근이 필요하다면 GitHub App 또는 적절한 OAuth 권한을 사용하고, 인증 토큰은 프론트엔드나 로그에 노출하지 않습니다. 저장소에 포함된 비밀번호·API 키 등의 민감정보는 LLM에 전달하기 전에 탐지·제외해야 합니다.

## 11. Neon PostgreSQL 데이터베이스 설계

|테이블|주요 필드|기능|
|---|---|---|
|`github_repositories`|repository_id, user_id, owner, repo_name, default_branch, github_repo_id|저장소 등록|
|`github_analysis_runs`|analysis_id, repository_id, commit_sha, status, started_at, completed_at|분석 실행 이력|
|`github_files`|file_id, analysis_id, path, file_type, size, sha|파일 목록|
|`github_commits`|commit_id, analysis_id, commit_sha, author, committed_at, message|Commit 이력|
|`github_analysis_results`|result_id, analysis_id, category, score, summary, findings_json|분석 결과|
|`github_analysis_findings`|finding_id, analysis_id, severity, file_path, evidence, recommendation|개선사항|
|`task_verifications`|verification_id, task_id, analysis_id, result, evidence_json|학습과제 검증|

`github_analysis_runs`에 분석 기준 Commit SHA를 저장하면, 이후 소스코드가 변경되어도 과거 분석 결과가 어떤 코드 상태를 기준으로 생성되었는지 추적할 수 있습니다.

## 3. OpenAI API가 실제로 수행하는 분석

예를 들어 학습자가 FastAPI 프로젝트를 GitHub에 등록했다고 가정하겠습니다.

GitHub API에서 `main.py`, `database.py`, `models.py`, `README.md`를 수집한 후 OpenAI API에 다음 작업을 요청합니다.

1. 프로젝트의 주요 기능과 기술 스택을 설명한다.
    
2. 코드 구조가 적절하게 분리되었는지 평가한다.
    
3. 오류 처리, 데이터 검증, 보안상 개선사항을 찾는다.
    
4. README에 부족한 내용을 확인한다.
    
5. 학습자의 과제 완료 기준과 실제 구현 코드를 비교한다.
    
6. 우선적으로 수정해야 할 사항 3개를 제시한다.
    

### Python 코드 구현 예시

```
from openai import OpenAIclient = OpenAI()def analyze_github_project(readme, source_code):    response = client.responses.create(        model="gpt-5.4-mini",        instructions=(            "당신은 AI 개발 프로젝트 평가자입니다. "            "제공된 코드와 README만 근거로 분석하세요. "            "확인되지 않은 기능은 구현되었다고 판단하지 마세요."        ),        input=f"""        [README]        {readme}        [SOURCE CODE]        {source_code}        다음 항목을 분석하세요.        1. 프로젝트 주요 기능        2. 기술 스택        3. 코드 구조의 적절성        4. 발견된 문제점        5. 개선 우선순위 3개        """    )    return response.output_text
```

위 코드는 OpenAI API 호출 부분만 보여주는 최소 예시입니다. 실제 서비스에서는 파일 크기 제한, 민감정보 제거, 오류 처리, JSON 구조화 출력, 분석 근거 검증이 추가되어야 합니다. 모델 사용 가능 여부도 API 계정에서 확인해야 합니다.

## 4. OpenAI API 없이 가능한 분석

OpenAI API를 사용하지 않아도 Python으로 다음 항목을 분석할 수 있습니다.

- 파일·폴더 개수 및 구성
    
- 사용 언어와 프레임워크 탐지
    
- README 존재 여부
    
- Commit 수 및 주간 활동량
    
- `requirements.txt` 분석
    
- Python AST 기반 함수·클래스 구조 추출
    
- Ruff 등의 도구를 활용한 정적 코드 검사
    

따라서 Python 기반의 정량·규칙 분석 + OpenAI 기반의 정성·의미 분석을 결합하는 것이 비용과 분석 신뢰성 측면에서 유리합니다.
