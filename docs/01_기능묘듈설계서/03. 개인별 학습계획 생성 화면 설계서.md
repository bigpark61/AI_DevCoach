# AI DevCoach — 개인별 학습계획 수립 화면설계서

화면설계서 v1.0 | 기능 ID: FR-03 | 연계 기능: FR-01 사용자 프로필, FR-02 수준 진단, FR-04 학습 진도 관리

## 1. 화면 설계 개요

목적: 학습자의 목표, 현재 역량, 취약 기술, 주당 학습 가능 시간을 종합하여 AI Agent가 개인별 학습계획을 생성하고, 사용자가 검토·수정·승인한 후 실제 학습 과제로 등록하도록 합니다.

핵심은 AI가 계획을 제안하고, 학습자가 승인한 계획만 실행 계획으로 확정하는 것입니다.

## 3. UI-11 AI 학습계획 생성 화면

사용자가 계획 생성을 요청하면 다음 과정을 수행합니다.

1. 학습자 정보 조회: 학습 목표, 관심 기술, 주당 학습 가능 시간, 최근 진단 결과를 불러옵니다.
    
2. 학습 목표 분해: Planning Agent가 최종 목표를 주차별 성취 목표로 분해합니다.
    
3. 선행학습 확인: Python → API → FastAPI → LLM 연동 등 필요한 기술 의존관계를 점검합니다.
    
4. 과제와 시간 배정: 주차별 학습 내용, 실습 과제, 예상시간, 제출 결과물을 구성합니다.
    
5. 계획 검증: 시간 초과, 필수 필드 누락, 과제 중복 및 비현실적인 목표를 확인합니다.
    
6. 미리보기 제공: 검증된 계획을 임시 상태로 표시하고 사용자 승인을 기다립니다.
    

생성 중에는 `학습자 분석 중 → 주차별 계획 작성 중 → 학습시간 검증 중 → 완료` 상태를 표시합니다. 이 상태는 실제 서버 처리 단계에 따라 갱신하며, 임의의 진행률을 보여주지 않습니다.

## 5. UI-13 계획 수정 및 승인 화면

### 5.1 수정 가능 항목

|수정 항목|사용자 조작|처리 방법|
|---|---|---|
|학습 목표|목표명 수정|관련 주차 목표 재검토|
|학습시간|주당 시간 변경|과제시간 재배분 요청|
|과제 순서|순서 변경|선행학습 위반 여부 검증|
|과제 난이도|난이도 변경|관련 과제 내용 재생성|
|과제 삭제|삭제|필수 목표 누락 여부 확인|
|과제 추가|추가|주간 총시간 검증|
|학습자료|자료 변경|대체 자료 선택|
|계획 전체|AI 재생성|기존 초안 보존 후 새 버전 생성|

### 5.2 승인 조건

계획을 확정하려면 다음 조건을 만족해야 합니다.

1. 모든 주차에 최소 1개 이상의 학습 과제가 존재해야 합니다.
    
2. 주차별 과제시간 합계가 사용자의 주당 가용시간을 초과하지 않아야 합니다.
    
3. 각 과제에 학습 목표, 예상시간, 완료 기준이 있어야 합니다.
    
4. 선행학습 관계가 논리적으로 유효해야 합니다.
    
5. 사용자가 최종 승인해야 합니다.
    

승인된 계획은 `approved` 상태로 저장하고, 해당 계획에 포함된 과제들을 FR-04 학습 진도 관리 기능에 등록합니다.

## 6. Planning Agent 설계

### 6.1 Agent 아키텍처

![[mermaid-diagram (3).png]]

### 6.2 Agent Tool 명세

|Tool 이름|기능|반환 데이터|
|---|---|---|
|`get_user_profile`|학습자 프로필 조회|목표, 가용시간, 선호 기술|
|`get_assessment_result`|최근 수준 진단 조회|총점, 수준, 영역별 점수|
|`get_learning_history`|기존 학습 이력 조회|완료 과제, 취약 영역|
|`get_learning_resources`|추천 학습자료 조회|자료명, URL, 난이도|
|`validate_learning_plan`|계획 구조·시간 검증|오류 목록, 검증 상태|
|`save_learning_plan_draft`|초안 저장|계획 ID, 버전|
|`approve_learning_plan`|사용자 승인 처리|확정 계획 ID|
|`create_learning_tasks`|학습 과제 등록|과제 ID 목록|

### 6.3 Agent 생성 규칙

Planning Agent에는 다음 규칙을 적용합니다.

- 진단 점수가 낮은 영역을 우선 보완하되, 사용자의 최종 목표와 관련성을 함께 고려합니다.
    
- 학습 수준에 적합한 난이도를 선택합니다.
    
- 각 주차의 총 예상시간이 가용시간을 넘지 않도록 합니다.
    
- 개념 학습과 실습을 적절히 조합합니다.
    
- 매주 GitHub 등에서 확인할 수 있는 결과물을 정의합니다.
    
- 완료 기준은 관찰하거나 확인할 수 있는 행동으로 작성합니다.
    
- 학습자료 URL을 생성할 경우 실제 존재 여부를 검증합니다.
    
- AI가 학습 완료 여부를 임의로 변경하지 않습니다.
    

중요: LLM은 계획을 생성하고 설명하는 역할을 맡으며, 시간 합계와 필수 필드 검증은 Python 코드에서 결정적으로 처리합니다.

## 8. Backend API 설계

|Method|Endpoint|기능|
|---|---|---|
|GET|`/api/plans/context`|프로필·진단 결과 조회|
|POST|`/api/plans/generate`|AI 학습계획 생성 요청|
|GET|`/api/plans/{plan_id}`|계획 상세 조회|
|PATCH|`/api/plans/{plan_id}`|계획 초안 수정|
|POST|`/api/plans/{plan_id}/regenerate`|AI 계획 재생성|
|POST|`/api/plans/{plan_id}/validate`|계획 검증|
|POST|`/api/plans/{plan_id}/approve`|계획 최종 승인|
|GET|`/api/plans/current`|현재 활성 계획 조회|

### 계획 생성 요청 예시

```
{
  "goal": "AI Agent 웹서비스 개발",
  "assessment_id": "assessment_001",
  "duration_weeks": 4,
  "weekly_hours": 8,
  "difficulty": "balanced",
  "learning_style": "project",
  "focus_skills": [
    "API·데이터 처리",
    "Git·GitHub"
  ],
  "additional_requirements": "GitHub 기초부터 학습"
}
```

### 계획 생성 응답 예시

```
{
  "plan_id": "plan_001",
  "status": "draft",
  "goal": "AI Agent 웹서비스 개발",
  "duration_weeks": 4,
  "weekly_hours": 8,
  "weeks": [
    {
      "week_no": 1,
      "weekly_goal": "GitHub 및 API 기초 역량 확보",
      "tasks": [
        {
          "title": "GitHub Branch 및 PR 실습",
          "estimated_hours": 3,
          "deliverable": "Pull Request",
          "completion_criteria": "Branch 생성 및 PR 제출"
        },
        {
          "title": "Python REST API 호출 실습",
          "estimated_hours": 5,
          "deliverable": "Python 소스코드",
          "completion_criteria": "API 응답을 JSON으로 파싱"
        }
      ]
    }
  ]
}
```

위 응답은 형식을 설명하는 축약 예시입니다. 실제 4주 계획에서는 4개 주차 데이터가 모두 반환되어야 합니다.

## 11. 최종 완료 기준

FR-03 개인별 학습계획 수립 기능은 다음 조건을 충족하면 완료로 판정합니다.

- 학습자의 프로필과 최신 수준 진단 결과를 자동으로 불러온다.
    
- 사용자가 목표·기간·시간·난이도·학습 방식을 설정할 수 있다.
    
- Planning Agent가 조건에 맞는 주차별 학습계획을 생성한다.
    
- 각 과제에 학습 목표, 예상시간, 결과물, 완료 기준이 포함된다.
    
- 계획의 시간·구조·선행학습 조건을 검증한다.
    
- 사용자가 계획을 수정하거나 재생성할 수 있다.
    
- 승인한 계획만 확정 상태로 저장한다.
    
- 확정된 계획이 FR-04 학습 진도 관리와 연동된다.
    

개발 시 가장 중요한 구현 포인트는 `진단 결과 → 계획 생성 → 사용자 승인 → 과제 등록`의 데이터 연결입니다. 이 기능이 완성되어야 AI DevCoach가 단순한 학습 추천 챗봇이 아닌 개인별 학습 관리 Agent로 동작할 수 있습니다.
