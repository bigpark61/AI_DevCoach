# AI 코치 대화 저장·복원 및 재계획 요청 화면 정리

## 범위와 출처
- 기준: `bigpark61/AI_DevCoach` main `c5e43b54a28cb3813be878e3f1c2fdb94d5b421c`.
- 팀이 전달한 `AI_devCoach_clone2.zip`에는 재계획 요청 폼 제거, 계정별 대화 저장/조회, 마이그레이션과 기본 복원 테스트가 이미 포함되어 있었다.
- 이 변경은 팀의 구현을 유지하고, 늦게 도착한 응답의 계정 혼입 방지·화면 복귀 방지·실패 시 입력 보존·회귀 테스트를 보강한다. 팀원이 먼저 구현한 기능을 새로 작성했다고 주장하지 않는다.

## 동작
1. 학습 코칭 화면에서 재계획 요청 입력 영역과 제출 버튼을 제거한다. 기존 학습 코칭 내용과 뒤로 가기는 유지한다.
2. 성공적으로 완료된 질문/답변과 출처를 인증된 사용자 ID로 DB에 저장한다.
3. 로그아웃은 세션과 브라우저 표시 상태만 비우고 저장 대화는 지우지 않는다.
4. 같은 계정으로 재로그인하고 AI 코치를 열면 전체 저장 대화를 불러온다.
5. AI 후속 답변의 문맥에는 DB에 저장된 최근 8개 메시지(최대 4쌍)를 사용한다. 화면 복원 이력은 이 제한으로 삭제하지 않는다.
6. 다른 계정의 대화는 조회하지 않는다. 클라이언트가 보낸 과거 대화는 신뢰하지 않고, 서버 이력만 AI 문맥에 사용한다.
7. 답변 생성 중 로그아웃·계정 변경·다른 화면 이동 시 늦은 응답이 새 화면을 덮지 않는다.
8. 생성 실패는 정상 답변으로 저장하지 않는다. 입력창에 질문을 되돌려 사용자가 재시도할 수 있게 한다.

## 검증 결과 (2026-11-16)
- `python -m unittest discover -s tests -v`: 30개 통과. 기존 21개 및 추가 9개.
- 추가 검증: 인증 필수, 계정 분리, 재로그인, 앱 재생성(DB 유지), 클라이언트 이력 무시, 최근 문맥 제한, AI 실패, 질문/답변 원자적 저장, 캐시 금지, 기존 SQLite 초기화 호환.
- `node --check frontend/app.js`: 통과.
- `python -m compileall -q backend migrations tests`: 통과.
- 새 마이그레이션: 임시 SQLite에서 upgrade/자동 ID insert/downgrade 통과.
- PostgreSQL: DDL 오프라인 컴파일 통과. 실제 클라우드 DB 적용은 하지 않았다.
- `tests/browser_chat_smoke.py`: Chromium DOM + 모의 API 7개 검사 통과. 로그아웃·재로그인 화면, 재계획 폼 제거, 실패 입력 복원, 계정 변경 중 늦은 응답, 원 계정 복원, 다른 화면 유지, JavaScript 오류 여부.
- 브라우저 검사는 온보딩을 테스트용 연결점으로 생략한다. 실제 로그인/저장/권한 API는 별도 백엔드 테스트에서 검사했다. 전체 실서비스 E2E 테스트를 완료했다는 뜻이 아니다.
- 외부 AI는 모의 응답으로 검사했다. 실제 유료 AI 호출, 운영 데이터 변경, 운영 배포, Windows PowerShell 실행은 하지 않았다.

## DB 적용
- SQLite: 앱 시작 시 `CREATE TABLE IF NOT EXISTS`로 대화 테이블이 생성된다. 기존 DB 파일은 지우지 않는다.
- PostgreSQL/Neon: 담당자가 DB 백업과 현재 revision을 확인한 뒤 `python -m alembic upgrade head`로 0004를 적용해야 한다. 배포 앱은 PostgreSQL 테이블을 자동 생성하지 않는다.
- 배포 파일시스템의 SQLite 파일이 사라지면 대화도 유지되지 않는다. 운영은 기존 Neon 또는 영속 스토리지를 사용한다.
- 답변 완료 전에 발생한 실패 요청, 저장 기능 도입 전 이미 없어진 대화는 복구 대상이 아니다.

## 최소 수동 검수
A 계정 질문/답변 -> 로그아웃 -> A 재로그인 -> AI 코치에서 복원 확인.
B 계정 로그인 -> A 대화가 없음을 확인.
A 계정에서 답변 대기 -> 로그아웃/B 로그인 -> 늦은 답변이 B에게 보이지 않음을 확인.
학습 코칭 -> 재계획 요청 영역만 사라지고 코칭이 유지되는지 확인.

## 배포 및 기록 주의
이 변경은 UI 제거와 대화 저장에 집중한다. 과거 재계획 요청 DB/API는 호환성과 기존 자료 보존을 위해 삭제하지 않았다.
현재 이력 API에는 페이지 나누기가 없다. 운영 규모가 커지면 별도 개선이 필요하다.
계정별 로그 저장을 새로 활성화할 때 서비스의 개인정보 안내·보관/삭제 정책도 팀에서 확인한다.
