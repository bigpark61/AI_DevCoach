## 기존 실패와 환경 오류

`tests/test_chat_persistence.py:166`의
`test_authenticated_history_cannot_be_cached`가 수정 전후 모두 실패한다.
GET /api/agent/history 응답에 기대한 Cache-Control: no-store가 없고 None이 반환된다.
관련 구현은 `backend/main.py:3023`의 agent_chat_history다. 캐시 정책 변경은
이번 lint 작업에서 수행하지 않았으며 테스트도 제거하거나 완화하지 않았다.
후속 작업은 이 응답의 Cache-Control 및 Vary 헤더를 검토하고 기존 테스트를 재실행하는 것이다.

처음에는 실행 환경의 SOCKS 프록시 변수 때문에 GitHub 분석 테스트도 오류를 냈다.
외부 요청을 모의 응답으로 처리하는 테스트 프로세스에서만 프록시 환경변수를 제외하여
환경 오류를 분리했다. 운영 코드와 의존성은 바꾸지 않았다. 이때 사용한 명령은 다음과 같다.

```bash
env -u ALL_PROXY -u all_proxy -u HTTP_PROXY -u http_proxy \
  -u HTTPS_PROXY -u https_proxy \
  .venv/bin/python scripts/check_quality.py --test
```

Starlette TestClient의 httpx 사용 중단 예정 경고도 관측했다. 경고를 숨기거나
의존성을 임의로 교체하지 않았다. 이 경고는 캐시 헤더 테스트 실패와 다른 문제다.

## 미검증 범위 및 후속 확인

- 선택적 tests/browser_chat_smoke.py는 기본 Chromium 실행 파일 부재로 실행하지 못했다.
  브라우저 설치는 다운로드 압축파일 오류로 실패했고, 설치된 /usr/bin/chromium을
  지정한 재시도도 실행 환경의 socket 권한 제한으로 시작하지 못했다. 따라서 브라우저
  테스트 통과를 주장하지 않는다.
- Windows PowerShell에서의 실제 실행은 사용자가 후속 확인한다. 스크립트는 Bash 변수 대신
  현재 Python 실행 파일, pathlib와 subprocess를 사용하여 Windows 실행을 지원하도록 작성했다.
- 운영 PostgreSQL·Neon 데이터, 실제 AI 및 이메일 호출, Vercel 운영 사이트, HTML/CSS lint,
  TypeScript 타입 검사와 보안 감사는 이 작업에서 검증하지 않았다.
- GitHub Actions를 새로 활성화하거나 실행하지 않았다. 후속 사용자 커밋은 [skip ci]를
  포함하도록 안내했다. main 병합 및 운영 배포는 이 작업에서 수행하지 않았다.
- 기존 테스트 실패를 해결한 후 동일 명령의 전체 통과를 확인하고 팀 검토를 마친다.
